# 恋人画像 Schema 与引导脚本

## 存储

- 路径：`~/.workbuddy/gift-picker/profiles/<昵称>.json`（UTF-8）
- 存储路径可通过环境变量 `GIFT_PICKER_HOME` 覆盖
- 通过 `scripts/profile_manager.py` 读写，禁止手工覆盖整个文件（用 set 增量合并）
- 写入前自动备份，写入失败自动恢复，原子写入防止中断损坏

## 字段定义

```json
{
  "schema_version": 2,
  "nickname": "称呼/昵称（文件名同名）",
  "relationship": "女朋友 | 老婆 | 心仪对象",
  "relationship_stage": "pursuit | honeymoon | stable | newlywed | anniversary | longterm",
  "relationship_start_date": "YYYY-MM-DD（可空）",
  "colors_like": ["喜欢的颜色"],
  "colors_dislike": ["排斥的颜色"],
  "skincare_brands": ["常用护肤品牌"],
  "makeup_brands": ["常用美妆品牌"],
  "style": "穿衣风格（如 简约通勤/甜美/复古/运动）",
  "scent": "喜欢的味道/香调（如 木质调/果香/无香）",
  "sizes": {
    "clothes": "衣服尺码 S/M/L 或具体",
    "shoes": "鞋码",
    "ring": "戒指圈口（可空）",
    "height_cm": 0,
    "weight_note": "体型备注（可空）"
  },
  "hobbies": ["兴趣爱好"],
  "allergies": ["过敏源（皮肤/食物）"],
  "diet_taboo": ["忌口"],
  "owned_items": ["已拥有的重要物品，避免重复送"],
  "budget_habit": "历史送礼预算习惯（可空）",
  "gift_history": [{"date": "YYYY-MM-DD", "gift": "礼物", "feedback": "反馈"}],
  "notes": "其他备注",
  "updated_at": "YYYY-MM-DD"
}
```

**`relationship_stage` 字段说明**：

| 值 | 含义 | 送礼倾向 |
|---|---|---|
| `pursuit` | 追求期（未在一起） | 低压力、有心意、价格适中 |
| `honeymoon` | 热恋期（0-6 个月） | 仪式感、高调、热情表达 |
| `stable` | 稳定期（半年以上） | 品质、实用、深度爱好 |
| `newlywed` | 新婚期（0-2 年） | 承诺、隆重、家庭导向 |
| `anniversary` | 周年纪念 | 回顾、感恩、数字纪念 |
| `longterm` | 长期陪伴（10 年+） | 贴心、健康、低调奢华 |

详细阶段策略见 `references/relationship-stages.md`。

## 字段合并规则

- `gift_history`：追加（append），每次 `set` 新增的条目追加到数组末尾
- `colors_like`、`colors_dislike`、`allergies`、`diet_taboo`、`owned_items`、`hobbies`、`skincare_brands`、`makeup_brands`：拼接合并（extend），自动去重
- 其他 list 字段：整体替换
- `null` 值：表示删除该键
- `dict` 字段（如 `sizes`）：递归合并

## Schema 版本迁移

- 当前版本：`schema_version: 1`
- 旧版画像（无 `schema_version` 字段）可通过 `python scripts/profile_manager.py migrate` 一键迁移
- 未来字段新增会通过升级 `schema_version` + 迁移脚本实现向后兼容

## 画像获取策略（按优先级，先材料后问答）

**核心原则：优先解析用户提供的现成材料，问答只用于补关键缺口。禁止在未尝试材料解析前从头逐题问到尾。**

### 模式 A：材料解析（首选，信息密度最高）

首次建画像时，先用一次交互式提问让用户选择获取方式，**主要 2 个选项**（截图和逐题问答作为 Other 或补充）：
1. **🔗 社媒 ID 一键画像**（最高优先，标注"推荐"）——用户提供她的小红书号/微博号/抖音号/B站号，按 `references/social-profiling.md` 自动检索公开媒体 → 分析喜好 → 对话内生成**不落盘**的喜好报告 → 用户确认后写入画像。
2. **✏️ 我来描述**——用户用一段话自由描述他知道的一切（喜好、品牌、尺码、她提过的话），AI 解析为结构化字段；解析结果中置信度低的字段标注"推测"。

（发截图、逐题问答作为补充手段，可通过 Other 输入或在上述方式完成后补缺。）

多种材料可组合。每份材料解析后，把提取结果向用户复述确认（一次性列出，允许口头纠正），确认后 `set` 保存。

### 模式 B：交互式问答（兜底 + 补缺）

**硬性要求**：使用交互式提问 UI（AskUserQuestion 工具），每批 1~3 个相关问题，每题给 2~4 个常见默认选项。用户选"跳过/不确定"则存 null，报告中相应维度降权。

**补缺规则**：模式 A 完成后，只补问缺失的**必答项**，其余缺口留空下次再补。必答项仅 1 个：
- 过敏/忌口（安全一票否决项，必须确认）

> **注意**：预算、关系阶段、品类倾向、评分偏好属于本次任务参数，不在画像问答中提问，统一在 SKILL.md 阶段 0（预算、关系阶段）和阶段 1（场景、品类倾向、评分偏好）中处理。

全量问答（用户无任何材料时）分 4 批提问（选项仅为常见默认值，可按上下文微调）：

**第 1 批**（基本信息，2 题同问）：

| # | 字段 | 问题 | 默认选项 |
|---|------|------|----------|
| 1 | relationship + nickname | 她是你的什么人？怎么称呼她？ | 女朋友 / 老婆 / 心仪对象（称呼可自由输入） |
| 2 | relationship_stage | 你们目前处于什么阶段？ | 追求期 / 热恋期 / 稳定期 / 新婚期 |

**第 2 批**（审美偏好，3 题同问）：

| # | 字段 | 问题 | 默认选项 |
|---|------|------|----------|
| 3 | colors_like + colors_dislike | 喜欢什么颜色？有排斥的吗？ | 白色系 / 粉色系 / 黑色系 / 大地色系（排斥的可自由输入） |
| 4 | style | 穿衣风格偏哪种？ | 简约通勤 / 甜美少女 / 复古文艺 / 运动休闲 |
| 5 | scent | 喜欢什么味道/香调？ | 果香甜香 / 花香 / 木质清冷 / 无香或不确定 |

**第 3 批**（实用信息，3 题同问）：

| # | 字段 | 问题 | 默认选项 |
|---|------|------|----------|
| 6 | skincare_brands + makeup_brands | 常用护肤/美妆品牌？ | 国际大牌 / 日系 / 国货 / 不清楚 |
| 7 | sizes | 衣服鞋码知道吗？ | S码左右 / M码左右 / 不清楚（可自由输入） |
| 8 | allergies + diet_taboo | 有过敏或忌口吗？ | 没有 / 皮肤敏感 / 有食物忌口（自由输入） |

**第 4 批**（兴趣与心愿，2 题同问）：

| # | 字段 | 问题 | 默认选项 |
|---|------|------|----------|
| 9 | hobbies | 她的兴趣爱好？（可多选） | 追剧游戏 / 运动健身 / 拍照旅行 / 手办香薰收藏（multiSelect: true） |
| 10 | owned_items + notes | 她最近提过想要什么？已有什么？ | 没听她提过 / 想不起来（自由输入为主） |

提问技巧：
- 4 批之间穿插简短进度反馈（如"还剩最后 2 个问题啦"），降低疲劳感。
- 与本次任务无关的字段可后置或省略，画像允许留空、下次补齐。
- 收集完成后向用户复述一遍摘要确认，再调用 `profile_manager.py set` 保存。

**本次任务参数**（不在画像问答中提问，按 SKILL.md 工作流处理）：
- 关系阶段：追求期 / 热恋期 / 稳定期 / 新婚期（周年纪念、长期陪伴走 Other）→ 阶段 0 ②
- 预算区间：建议区间 / 低于建议 / 高于建议 / 自定义 → 阶段 0 ③
- 品类倾向：首饰配饰 / 美妆香氛 / 兴趣周边 / 没想法帮我推荐（multiSelect 可选）→ 阶段 1
- 评分偏好：均衡 / 性价比优先 / 品质优先 / 浪漫优先 → 阶段 1

## 更新原则

- 增量合并：只传变化字段。
- `gift_history` 为追加数组；每次任务成功交付后，建议询问用户是否记录本次所送礼物与反馈，便于下次避重与优化。
- 敏感性提醒：画像属于隐私数据，仅存本机，不写入报告以外的任何输出，不上传。
- 存储路径可通过环境变量 `GIFT_PICKER_HOME` 自定义。
