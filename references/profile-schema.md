# 恋人画像 Schema 与引导脚本

## 存储

- 路径：`~/.workbuddy/gift-picker/profiles/<昵称>.json`（UTF-8）
- 通过 `scripts/profile_manager.py` 读写，禁止手工覆盖整个文件（用 set 增量合并）。

## 画像获取策略（按优先级，先材料后问答）

**核心原则：优先解析用户提供的现成材料，问答只用于补关键缺口。禁止在未尝试材料解析前从头逐题问到尾。**

### 模式 A：材料解析（首选，信息密度最高）

首次建画像时，先用一次交互式提问让用户选择获取方式，选项为：
1. **社媒 ID 一键画像**（最高优先）——用户提供她的小红书号/微博号/抖音号/B站号，按 `references/social-profiling.md` 自动检索公开媒体 → 分析喜好 → 对话内生成**不落盘**的喜好报告 → 用户确认后进入礼物检索。
2. **发截图给我**——她的小红书收藏夹/点赞页、淘宝购物车/收藏夹、微信聊天中提过想要东西的片段、朋友圈穿搭照。收到图片后用视觉能力提取：常出现的色系、品牌、风格关键词、明示的心愿物品，逐项映射到画像字段。
3. **一段话速写**——让用户用一段话自由倾倒他知道的一切（喜好、品牌、尺码、她提过的话），AI 解析为结构化字段；解析结果中置信度低的字段标注"推测"。
4. **逐题问答**——用户没有任何材料时才走模式 B。

多种材料可组合。每份材料解析后，把提取结果向用户复述确认（一次性列出，允许口头纠正），确认后 `set` 保存。

### 模式 B：交互式问答（兜底 + 补缺）

**硬性要求**：使用交互式提问 UI（AskUserQuestion 工具），**每次只问 1 个问题**，每题给 2~4 个常见默认选项（UI 自带自由输入，无需"其他"选项）。用户选"跳过/不确定"则存 null，报告中相应维度降权。

**补缺规则**：模式 A 完成后，只补问缺失的**必答项**，其余缺口留空下次再补。必答项仅 2 个：
- 过敏/忌口（安全一票否决项，必须确认）
- 本次预算区间

全量问答（用户无任何材料时）按以下顺序逐题提问（选项仅为常见默认值，可按上下文微调）：

| # | 字段 | 问题 | 默认选项示例 |
|---|---|---|---|
| 1 | relationship | 她是你的？ | 女朋友 / 老婆 / 心仪对象 |
| 2 | nickname | 怎么称呼她？（用作画像名） | 自由输入为主，选项可给：她 / 宝宝 |
| 3 | colors_like | 她喜欢什么颜色？ | 白色系 / 粉色系 / 黑色系 / 大地色系 |
| 4 | colors_dislike | 有排斥的颜色吗？ | 没有特别排斥 / 荧光亮色 / 不确定 |
| 5 | style | 穿衣风格偏哪种？ | 简约通勤 / 甜美少女 / 复古文艺 / 运动休闲 |
| 6 | skincare_brands + makeup_brands | 常用的护肤/美妆品牌？ | 国际大牌（雅诗兰黛/兰蔻等） / 日系（SK-II/CPB等） / 国货（花西子/珀莱雅等） / 不清楚 |
| 7 | scent | 喜欢什么味道/香调？ | 果香甜香 / 花香 / 木质清冷 / 无香或不确定 |
| 8 | sizes | 衣服尺码/鞋码知道吗？ | S码左右 / M码左右 / 不清楚（可自由输入具体尺码） |
| 9 | allergies + diet_taboo | 有皮肤过敏或食物忌口吗？ | 没有 / 皮肤敏感 / 有食物忌口（自由输入具体） |
| 10 | hobbies | 她的兴趣爱好？（可多选） | 追剧游戏 / 运动健身 / 拍照旅行 / 手办香薰收藏（multiSelect: true） |
| 11 | owned_items / notes | 她最近提过想要什么、或已经有什么（避免撞款）？ | 没听她提过 / 想不起来（自由输入为主） |

提问技巧：
- 每 3~4 题之间可穿插一句简短的进度反馈（如"还剩 3 个问题"），降低疲劳感。
- 与本次任务无关的字段可后置或省略（如送首饰可跳过尺码题以外的护肤品牌题），画像允许留空、下次补齐。
- 收集完成后向用户复述一遍摘要确认，再调用 `profile_manager.py set` 保存。

**本次任务参数**（画像之外，同样逐题交互式问）：
- 预算区间：200 以内 / 200~500 / 500~1000 / 1000 以上
- 品类倾向：首饰配饰 / 美妆香氛 / 兴趣周边 / 没想法帮我推荐（multiSelect 可选）

## 更新原则

- 增量合并：只传变化字段。
- `gift_history` 为追加数组；每次任务成功交付后，建议询问用户是否记录本次所送礼物与反馈，便于下次避重与优化。
- 敏感性提醒：画像属于隐私数据，仅存本机，不写入报告以外的任何输出，不上传。
