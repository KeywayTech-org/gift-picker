# 恋人画像 Schema 与引导脚本

## 存储

- 路径：`~/.workbuddy/gift-picker/profiles/<昵称>.json`（UTF-8）
- 存储路径可通过环境变量 `GIFT_PICKER_HOME` 覆盖
- 通过 `scripts/profile_manager.py` 读写，禁止手工覆盖整个文件（用 set 增量合并）
- 写入前自动备份，写入失败自动恢复，原子写入防止中断损坏

## 字段定义

```json
{
  "schema_version": 1,
  "nickname": "称呼/昵称（文件名同名）",
  "relationship": "女朋友 | 老婆 | 心仪对象",
  "relationship_stage": "pursuit | honeymoon | stable | newlywed | anniversary | longterm",
  "relationship_start_date": "YYYY-MM-DD（可空）",
  "colors_like": ["喜欢的颜色"],
  "colors_dislike": ["排斥的颜色"],
  "skincare_brands": ["常用护肤品牌"],
  "makeup_brands": ["常用美妆品牌"],
  "style": "穿衣风格（如 简约通勤/甜美/复古/运动）",
  "scent": "喜欢的味道/香调（如 木质调/果香/无香）",
  "sizes": {
    "clothes": "衣服尺码 S/M/L 或具体",
    "shoes": "鞋码",
    "ring": "戒指圈口（可空）",
    "height_cm": 0,
    "weight_note": "体型备注（可空）"
  },
  "hobbies": ["兴趣爱好"],
  "allergies": ["过敏源（皮肤/食物）"],
  "diet_taboo": ["忌口"],
  "owned_items": ["已拥有的重要物品，避免重复送"],
  "budget_habit": "历史送礼预算习惯（可空）",
  "gift_history": [{"date": "YYYY-MM-DD", "gift": "礼物", "feedback": "positive|neutral|negative", "note": "可选备注"}],
  "notes": "其他备注",
  "updated_at": "YYYY-MM-DD"
}
```

**`relationship_stage` 字段说明**：

| 值 | 含义 | 送礼倾向 |
|---|---|---|
| `pursuit` | 追求期（未在一起） | 低压力、有心意、价格适中 |
| `honeymoon` | 热恋期（0-6 个月） | 仪式感、高调、热情表达 |
| `stable` | 稳定期（半年以上） | 品质、实用、深度爱好 |
| `newlywed` | 新婚期（0-2 年） | 承诺、隆重、家庭导向 |
| `anniversary` | 周年纪念 | 回顾、感恩、数字纪念 |
| `longterm` | 长期陪伴（10 年+） | 贴心、健康、低调奢华 |

详细阶段策略见 `references/relationship-stages.md`。

## 字段合并规则

- `gift_history`：追加（append），每次 `set` 新增的条目追加到数组末尾
- `colors_like`、`colors_dislike`、`allergies`、`diet_taboo`、`owned_items`、`hobbies`、`skincare_brands`、`makeup_brands`：拼接合并（extend），自动去重
- 其他 list 字段：整体替换
- `null` 值：表示删除该键
- `dict` 字段（如 `sizes`）：递归合并

## Schema 版本迁移

- 当前版本：`schema_version: 1`
- 旧版画像（无 `schema_version` 字段）可通过 `python scripts/profile_manager.py migrate` 一键迁移
- 未来字段新增会通过升级 `schema_version` + 迁移脚本实现向后兼容

## 画像获取策略（按优先级，先材料后问答）

**核心原则：优先解析用户提供的现成材料，问答只用于补关键缺口。禁止在未尝试材料解析前从头逐题问到尾。**

### 模式 A：材料解析（首选，信息密度最高）

首次建画像时，先用一次交互式提问让用户选择获取方式，选项为：
1. **社媒 ID 一键画像**（最高优先）——用户提供她的小红书号/微博号/抖音号/B站号，按 `references/social-profiling.md` 自动检索公开媒体 → 分析喜好 → 对话内生成**不落盘**的喜好报告 → 用户确认后进入礼物检索。
2. **发截图给我**——她的小红书收藏夹/点赞页、淘宝购物车/收藏夹、微信聊天中提过想要东西的片段、朋友圈穿搭照。收到图片后用视觉能力提取：常出现的色系、品牌、风格关键词、明示的心愿物品，逐项映射到画像字段。
3. **一段话速写**——让用户用一段话自由倾倒他知道的一切（喜好、品牌、尺码、她提过的话），AI 解析为结构化字段；解析结果中置信度低的字段标注"推测"。
4. **逐题问答**——用户没有任何材料时才走模式 B。

多种材料可组合。每份材料解析后，把提取结果向用户复述确认（一次性列出，允许口头纠正），确认后 `set` 保存。

### 模式 B：交互式问答（兜底 + 补缺）

**硬性要求**：使用交互式提问 UI（AskUserQuestion 工具），每批 1 个相关问题，每题给 2~4 个常见默认选项。用户选"跳过/不确定"则存 null，报告中相应维度降权。

**补缺规则**：模式 A 完成后，只补问缺失的**必答项**，其余缺口留空下次再补。必答项仅 1 个：
- 过敏/忌口（安全一票否决项，必须确认）

> ⚠️ **安全例外**：过敏/忌口是唯一允许在"零追问"模式下追问的项。即使用户选择了"我来描述"/"社媒ID"/"发截图"路径，如果材料中未包含过敏信息，也**必须**用一次提问确认："为了安全，只问这一条——她有过敏或忌口吗？"这是安全底线，不适用零追问规则。

> **注意**：预算属于本次任务参数，统一在 SKILL.md Step 3（预算）中处理；**关系阶段在画像中持久化**（见 SKILL.md Step 2），每次任务可确认或更新，画像已有值时作为默认值带出。**品类倾向和评分偏好完全由系统自动决定，绝对禁止询问用户。**

全量问答（用户无任何材料时）分 3 批提问（选项仅为常见默认值，可按上下文微调）：

> 💡 **关系阶段不在此提问，由 SKILL.md Step 2 单独处理。**

**第 1 批**（基本 + 安全，3 题同问）：

| # | 字段 | 问题 | 默认选项 |
|---|------|------|----------|
| 1 | relationship + nickname | 她是你的什么人？怎么称呼她？ | 女朋友 / 老婆 / 心仪对象（称呼可自由输入） |
| 2 | colors_like + style + scent | 喜欢什么颜色和风格？香调呢？ | 白色系+简约通勤 / 粉色系+甜美少女 / 大地色系+复古文艺 / 不确定（香调可自由输入） |
| 3 | allergies + diet_taboo | 有过敏或忌口吗？（安全必问） | 没有 / 皮肤敏感 / 有食物忌口（自由输入） |

**第 2 批**（实用 + 爱好，2 题同问）：

| # | 字段 | 问题 | 默认选项 |
|---|------|------|----------|
| 4 | skincare_brands + makeup_brands | 常用护肤/美妆品牌？ | 国际大牌 / 日系 / 国货 / 不清楚 |
| 5 | sizes + hobbies | 衣服鞋码？她的兴趣爱好？（可多选） | S码+追剧游戏 / M码+运动健身 / 不清楚+拍照旅行（尺码和爱好可自由输入/多选） |

**第 3 批**（心愿 + 已有，1 题）：

| # | 字段 | 问题 | 默认选项 |
|---|------|------|----------|
| 6 | owned_items + notes | 她最近提过想要什么？已有什么重要物品？ | 没听她提过 / 想不起来（自由输入为主） |

提问技巧：
- 3 批之间穿插简短进度反馈（如"还剩最后 1 个问题啦"），降低疲劳感。
- 每批最多 3 题，合并相关字段（如颜色+风格+香调合成一题）。
- 与本次任务无关的字段可后置或省略，画像允许留空、下次补齐。
- 收集完成后向用户复述一遍摘要确认，再调用 `profile_manager.py set` 保存。

**本次任务参数**（不在画像问答中提问，按 SKILL.md 工作流处理）：
- 预算区间：建议区间 / 低于建议 / 高于建议 / 自定义 → SKILL.md Step 3
- 品类倾向：**由系统根据画像字段自动推断，绝对禁止询问用户**
- 评分偏好：**固定为均衡权重（20/25/20/15/20），绝对禁止询问用户**

## 画像完整度算法

用于评估画像信息充分程度（0~100），在 Step 1 保存后反馈缺失项，帮助提升推荐精度。

| 权重 | 字段 |
|------|------|
| 必填（各 15%） | nickname, relationship, relationship_stage, allergies |
| 重要（各 10%） | colors_like, style, hobbies, skincare_brands |
| 辅助（各 5%） | scent, sizes, makeup_brands, owned_items |
| 可选（0%） | notes, gift_history, budget_habit |

**计算口径**：完整度 = Σ(已填字段权重)。"已填"指字段存在且非空——list/dict 非空、字符串非空；`null` 或空值不计入。

## 更新原则

- 增量合并：只传变化字段。
- `gift_history` 为追加数组；每次任务成功交付后，建议询问用户是否记录本次所送礼物与反馈，便于下次避重与优化。
- 敏感性提醒：画像属于隐私数据，仅存本机，不写入报告以外的任何输出，不上传。
- 存储路径可通过环境变量 `GIFT_PICKER_HOME` 自定义。
